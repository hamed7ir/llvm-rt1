==========================

This package has CHANGED binaries built from the LLVM Project.

The Apache License v2.0 with LLVM Exceptions, section 4(b), says changed files must carry a clear

WHAT THIS IS
------------

rt2.1 is a full toolchain for compiling C and C++ for 32-bit ARM Windows (thumbv7) with clang-cl
and lld-link. It is LLVM 23.1.1 with 16 patches.

  build         : 2026-10-05, clang e240ad76c3a4429084c026fe0a9b0fce34025032
  upstream base : llvmorg-23.1.1
  built from    : patches/rt21-vs-23.1.1.patch, the full diff from clean llvmorg-23.1.1. It was
                  made from the two source trees and checked by applying it to a fresh 23.1.1
                  and comparing file for file.
  the revision  : e240ad76c3a4429084c026fe0a9b0fce34025032 is the first 40 hex digits of the
                  sha256 of that diff. So the binaries name the exact source they came from.

The toolchain archive has 373 files:

  bin/                    29 tools (28 programs and libclang.dll), built from the changed source.
                          Also 8 Microsoft VC runtime DLLs. Those are not mine and not changed,
                          see below.
  lib/clang/23/include/   303 resource headers that go with this clang
  lib/clang/23/lib/windows/
                          clang_rt.builtins-arm.lib, clang_rt.builtins-i386.lib,
                          clang_rt.builtins-x86_64.lib and clang_rt.profile-x86_64.lib. All four
                          are built by this clang from rt2.1's own compiler-rt source. The ARM one
                          is the plain library, without the __rt_*div routines.
  staged/rtdiv/           an ARM builtins library WITH __rt_udiv/__rt_sdiv routines. It's a
                          fallback and is not used unless you copy it in. See its README.txt.
  patches/                rt21-vs-23.1.1.patch (the full diff) and origin/ (every patch on its
                          own, see origin/README.txt)
  runtime/                aeabi-shim.c, and an ARM32 .lib and .obj built from it by this clang
  licenses/               libxml2's license
  README.md, RELEASE-NOTES.md, LICENSE.TXT, MODIFICATIONS.txt

The dev archive (rt2.1-23.1.1-rt2.1-dev-win64) is LLVM's libraries, headers and CMake files from
the same build, so this notice covers it too. So does the copy of LLVM linked into the rustc in
the rustc archive.

------------------------------

  the 4 clang programs  --version prints
                        "Varan clang version 23.1.1-rt2.1 (e240ad76c3a4429084c026fe0a9b0fce34025032)"
  the 5 lld programs    print "Varan LLD 23.1.1". lld drops the suffix, so check lld by its
                        sha256, not by its version string.
  the llvm-* tools      most print "LLVM version 23.1.1-rt2.1". llvm-lib, llvm-ml, llvm-rc
                        and llvm-mt have no version flag, so check those by sha256.

    rt21fix-wip                                 any work-in-progress build of this one

WHAT WAS CHANGED
----------------

16 changes, all mine. They ship as one checked diff (patches/rt21-vs-23.1.1.patch) and one by one
in patches/origin/.

From rt2 (first written for LLVM 18 as rt1 patches, then moved to 23.x. origin/README.txt says
exactly how 0004 and 0007 differ from the rt1 versions):
  0002  lld/COFF: a locally defined dllimport function's __imp_ pointer lost the Thumb bit.
  0003  ARM: registers forwarded through a musttail call were not treated as live.
  0004  MC/CodeView: a tuple register in a DBG_VALUE crashed the backend.
  0005  tests for the this-adjusting thunk cases of 0003.
  0007  ARM: a musttail vararg forwarder that also calls va_start crashed the backend.
  0010  clang: _setjmp on Windows ARM32 got the frame pointer instead of the entry stack pointer.
New in rt2.1:
  0011  clang: _ReadWriteBarrier, _ReadBarrier and _WriteBarrier are built in on 32-bit Arm.
  0012  clang and ARM: 26 MSVC ARM intrinsics, and _AddressOfReturnAddress.
  0013  clang: the lifetime_capture_by(this) deprecation warning is off by default.
  0014  clang: pcs("aapcs-vfp") is accepted on Windows on Arm, where it is the default anyway.
  0015  lld/COFF: no range-extension thunk on a branch that is in range, and safety margins
        per relocation type.
  0016  ARM: COFF objects carry @feat.00, so lld reads their /guard:cf tables.
  0017  ARM: C++ exception handling (WinEH, __CxxFrameHandler3) on Windows.
  0018  lld/COFF: IMAGE_REL_ARM_BRANCH20T writes the J1 and J2 bits the right way round.
  0019  test only: 0007's test updated for LLVM 23.
  0020  ARM: _AddressOfReturnAddress saves LR in a leaf function, and keeps {r7, lr} next to
        each other on ELF Thumb2. This finishes 0012's _AddressOfReturnAddress.

Every patch from 0012 on has lit tests that fail without it, and an independent review. The
changes those reviews caused were reviewed again.


THIRD-PARTY CODE INSIDE THE TOOLS: libxml2
------------------------------------------

lld-link (and its other names lld, ld.lld, ld64.lld, wasm-ld) and llvm-mt are linked with a
STATIC libxml2 2.15.4. That's how lld-link can merge and embed manifests without mt.exe. libxml2
is not part of LLVM and not mine. It is copyright the libxml2 authors, under the MIT license. The
full text is licenses/libxml2-Copyright.txt.

I did not change libxml2's source. It is the released libxml2-2.15.4.tar.xz, checked against its
published sha256. I built it as a static library with ICU, iconv, zlib, HTTP and modules turned
off. Two build-side additions, neither one touches libxml2's code: a one-line header forced into
every libxml2 object that tells the linker to use bcrypt.lib (libxml2's dict.c calls
BCryptGenRandom), and LIBXML_STATIC defined in the installed xmlexports.h, so programs using the
static library don't need to pass it.


THE VC RUNTIME, AND WHY bin/ HAS EIGHT MICROSOFT DLLs
------------------------------------------------------

  concrt140.dll   msvcp140.dll   msvcp140_1.dll   msvcp140_2.dll
  vcruntime140.dll   vcruntime140_1.dll   msvcp140_atomic_wait.dll
  msvcp140_codecvt_ids.dll

These tools are built with the Visual Studio 2022 14.44 toolset and need MSVCP140.dll. Shipping
the matching runtime means the toolchain works on its own.

These are MICROSOFT's redistributable files, from the Visual Studio 2022 14.44 build tools.
Microsoft lets you pass them on under the "Distributable Code" terms of the Visual Studio license
(see Microsoft's page on redistributable files for Visual Studio 2022). They are NOT under the
Apache-2.0 license in LICENSE.TXT, I did not change them, and I don't claim any copyright in them.

If you don't want Microsoft binaries from me, delete all eight from bin/. Then every tool uses
your system copy instead, as long as it is 14.44 or newer.


WHAT WAS NOT CHANGED
--------------------

Nothing about layout, ABI or calling conventions was moved AWAY from MSVC. The changes that touch
ABI-visible behaviour move clang TOWARD MSVC: 0012 expands the intrinsics like cl does, 0014
treats pcs("aapcs-vfp") as the convention Windows on Arm already uses, 0016 emits the @feat.00
symbol cl emits, and 0017 builds the C++ exception tables, funclets and frames that MSVC's runtime
reads, including MSVC's rule that such a frame is never realigned.
